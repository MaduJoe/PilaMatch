# TC-01 [P0] 스튜디오 → 계약 확정 → 결제 성공 → 에스크로 HELD 반영
**목적:** 결제 성공 후 “HELD”로 보관되는지 확인 (중복 결제/상태 오염 방지) :contentReference[oaicite:7]{index=7}  
**플랫폼:** iOS/Android/Web 모두

**Given**
- Studio_Free 로그인
- Instructor_Free와 매칭 후 계약 생성 가능 상태

**When**
1) Studio_Free가 계약 확정(결제 요청)
2) 토스 결제 성공(결제 완료 응답 수신)

**Then (기대)**
- UI: 계약 상태가 진행 상태로 전환(결제 완료 표시)
- DB/API: payment 생성, escrow_status = HELD (결제 후 플랫폼 보관) :contentReference[oaicite:8]{index=8}
- 재진입(새로고침/앱 재실행) 시에도 동일 상태로 복구(중복 생성 없음)

# TC-02 [P0] 결제 confirm 중복(더블클릭/새로고침)에도 “중복 결제/중복 payment” 0
**목적:** 사용자가 결제 버튼 연타/새로고침 시에도 payment 1개만 생성

**Given**
- TC-01 전 단계(결제창 진입 직전 또는 confirm 직후 응답 지연 상황)

**When**
1) 결제 confirm 요청을 2~3회 반복 발생시키기(연타/새로고침)
2) 또는 결제 성공 후 클라가 응답 못 받은 상황을 재현

**Then**
- DB: 동일 contract_id에 payment 레코드는 1개(혹은 idempotency 키 기준 1회만)
- UI: “결제 완료” 화면 1회만 노출, 결제 내역이 중복되지 않음
- 에러가 나더라도 “이미 처리됨” 형태로 안전하게 수렴

# TC-03 [P0] 결제 실패/취소/시간초과 시 상태 오염 방지
**목적:** 실패했는데 IN_PROGRESS/HELD로 남는 케이스 차단

**Given**
- TC-01과 동일

**When**
- 토스 결제: 실패/사용자 취소/시간초과 각각 1회씩 실행

**Then**
- UI: 결제 실패 안내 + 재시도 가능
- DB/API: escrow_status가 HELD/RELEASED로 절대 가지 않음(또는 payment.status=FAILED/CANCELLED)
- 계약 상태는 결제 완료로 표시되지 않음
