가장 간단하게 하려면 **“실제 사용처럼 보이는 1분짜리 시나리오 기반 화면녹화”**로 가는 게 맞습니다.
지금 상태에서는 **브랜딩 영상**보다 **제품 데모 영상**이 더 효과적입니다. 특히 타겟이 “커뮤니티 구인구직에 지친 센터장”이면, 예쁜 영상보다 **문제 해결 속도와 신뢰**가 바로 보여야 합니다. 업로드한 시나리오도 그 방향이 잘 잡혀 있습니다. 핵심 메시지는 **“호호요가 게시판보다 10배 빠르고 안전한 긴급 대타 매칭”**이고, 장면도 `긴급 등록 → 자동 매칭 → 인수인계 → GPS 체크인 → 완료 확인` 순서로 이미 정리돼 있습니다. 

실행 방식은 복잡하게 가지 말고 아래처럼 하면 됩니다.

## 가장 쉬운 제작 방식

**1. 앱 화면 2개만 준비**

* 센터 화면: Chrome
* 강사 화면: Edge

이건 업로드한 촬영 가이드와 동일합니다. 모바일 뷰로 375x812처럼 맞추면 “실제 현장용 앱” 느낌이 강해집니다. Chrome DevTools의 Device Mode는 모바일 뷰포트와 센서 시뮬레이션을 지원하고, Edge DevTools도 Device Emulation으로 모바일 환경을 근사하게 재현할 수 있습니다. ([Chrome for Developers][1])

**2. 실제 데이터처럼 보이는 더미 데이터 세팅**
영상이 리얼해 보이려면 UI보다 **데이터가 진짜 같아야** 합니다.
이미 시나리오에 필요한 계정, 위치, 공고, 인수인계 노트가 정리돼 있으니 그대로 seed 데이터로 넣으면 됩니다. 특히 아래 4개가 중요합니다. 

* 센터명: 실제 있을 법한 이름
* 강사 거리: 2.3km, 5.1km처럼 구체적 숫자
* 수업 조건: “5:1 타워리포머 / 중급 / 60분”
* 회원 특이사항: “허리디스크 주의”처럼 디테일한 handoff note

사용자는 “앱이 있네”보다 “이거 당장 우리 센터 문제 해결하겠네”를 봅니다.

**3. 녹화는 OBS 하나로**
OBS는 장면(Scene)과 소스(Source)를 조합해 브라우저 화면, 웹캠, 텍스트 등을 한 번에 구성할 수 있습니다. 공식 가이드도 장면/소스를 기본 단위로 설명합니다. ([OBS Project][2])
구성은 딱 4개면 충분합니다.

* Scene A: 센터 화면 단독
* Scene B: 강사 화면 단독
* Scene C: 좌우 분할
* Scene D: 마지막 웹캠 멘트

이 정도면 편집도 거의 필요 없습니다.

## 리얼하게 보이게 만드는 핵심

사용자는 “이게 진짜 돌아가는 제품인가?”를 무의식적으로 봅니다. 그래서 아래 5가지만 챙기면 됩니다.

### 1) 클릭이 아니라 “상황”을 보여줘야 함

단순히 버튼 기능 소개를 하면 데모 같고,
**“오늘 6:30 수업 펑크 → 긴급 등록 → 2초 뒤 강사 수락”**처럼 보여주면 실제 운영 툴처럼 보입니다.
업로드한 시나리오의 Scene 1 구조가 정확히 이 방식입니다. 

### 2) 속도감

타겟은 센터장이므로 가장 먼저 반응하는 포인트는 기능 수보다 **시간 절약**입니다.
영상 초반 10초 안에 아래 문장을 체감시키는 게 중요합니다.

> “게시판에 올리고 기다리는 대신, 자동으로 가장 가까운 강사에게 즉시 연결”

이건 자막과 화면 반응 속도로 보여주는 게 좋습니다. 같은 메시지는 시나리오 자막에도 반영돼 있습니다. 

### 3) 알림/상태 변화가 보여야 함

리얼한 데모는 “페이지 이동”보다 **상태 변화**가 살아 있어야 합니다.

* 긴급 공고 등록 후
* 강사 쪽 알림 도착
* 수락 후 센터 쪽 “매칭 완료”
* 체크인 후 “강사 도착”
* 완료 후 정산 기록

이 흐름이 살아 있으면 사용자는 백엔드까지 연결된 제품처럼 인식합니다. 시나리오의 `dispatch-status-widget`, `push-provider`, `job-progress-tracker` 구성이 이 포인트를 잘 잡고 있습니다. 

### 4) 얼굴 5~10초 넣기

마지막에 짧게 직접 말하는 장면이 있으면 신뢰도가 크게 올라갑니다.
특히 콜드메일이나 DM 발송용이면, 완성도 높은 광고보다 **“직접 만든 제품을 보여주는 창업자/개발자”** 느낌이 더 설득력 있습니다.
업로드한 마무리 장면도 같은 방향입니다. 

### 5) 완벽한 라이브보다 “통제된 라이브”

진짜 라이브로 다 찍으면 버벅임이 생길 수 있습니다.
가장 쉬운 방식은:

* 실제 앱으로 핵심 흐름만 재현
* 실패 가능성이 있는 부분은 사전 세팅
* 필요한 경우 Playwright로 미리 캡처/재현

Playwright는 브라우저 컨텍스트별로 독립 세션을 만들 수 있고, 디바이스/뷰포트/지오로케이션까지 에뮬레이션할 수 있으며, 스크린샷 자동 캡처도 지원합니다. ([Playwright][3])

## 지금 당신한테 가장 맞는 제작 프로세스

### 방법 A. 제일 빠른 방식

**실제 앱 + 수동 조작 + OBS 녹화 + CapCut 자막**

이게 제일 현실적입니다.

순서:

1. 로컬/스테이징 앱 실행
2. 센터 계정, 강사 계정 각각 로그인
3. 알림/위치/mock data 미리 세팅
4. OBS로 1080p 녹화
5. CapCut에서 자막만 넣기

업로드한 가이드도 OBS + CapCut + 1920x1080 + 하단 자막 구성을 권장하고 있습니다. 

이 방식이 좋은 이유:

* 지금 있는 앱으로 바로 가능
* 추가 개발이 적음
* 실제 데모처럼 보임
* 커뮤니티 피로 문제를 빠르게 검증 가능

### 방법 B. 더 안정적인 방식

**Playwright로 핵심 장면 자동 재현 + 녹화/스크린샷 조합**

영상 촬영 전에 아래 9개 화면을 미리 안정적으로 확보하면 좋습니다.

* 센터 대시보드
* 긴급 공고 등록
* 강사 알림 수신
* 수락 다이얼로그
* 센터 매칭 완료
* 인수인계 노트
* GPS 체크인
* 도착 알림
* 완료 확인

이 캡처 목록도 업로드 파일에 이미 정리돼 있습니다. 

이 방식이 좋은 이유:

* 데모 실패 확률이 낮음
* 여러 번 다시 찍기 쉬움
* 나중에 랜딩페이지/콜드메일용 이미지에도 재사용 가능

## Claude Code로 바로 시킬 작업

지금 상황에서는 Claude Code에게 **“영상 제작용 데모 안정화 작업”**만 시키는 게 좋습니다.
기능 개발을 더 하지 말고, 데모 연출용 보조 기능을 만들게 하세요.

### 1. 데모 seed 데이터 생성

Claude Code에 이렇게 요청하면 됩니다.

```text
현재 앱 기준으로 데모 영상용 seed 데이터를 추가해줘.

목표:
- 센터 계정 1개, 강사 계정 3개 생성
- 센터 위치와 강사 위치를 고정값으로 저장
- 긴급 공고 1개를 즉시 생성 가능하게 준비
- handoff note 더미 데이터 포함
- 데모 실행 시 항상 같은 결과가 나오게 해줘

데이터 조건:
- 센터: 트루바디필라테스 / 서울 양천구
- 강사 A: 2.3km
- 강사 B: 5.1km
- 강사 C: 12km
- 공고: 필라테스, 그룹 5:1 타워리포머, 30,000원, 오후 6:30, 긴급 모드 ON
```

### 2. 데모 모드 토글 추가

```text
앱에 demo mode를 추가해줘.

요구사항:
- URL query 또는 env flag로 활성화
- 알림, 매칭, 체크인 흐름이 2~3초 안에 재현되도록 처리
- 외부 API 실패 없이 더미 응답 사용 가능
- 데모용 배지/워터마크는 숨김 가능하게
```

### 3. Playwright 데모 스크립트 생성

```text
Playwright로 demo-video.spec.ts를 만들어줘.

목표:
- 센터(Chrome 계열), 강사(Edge 계열) 두 세션 분리
- 모바일 viewport 375x812
- geolocation mock 적용
- 알림 권한 허용
- 아래 순서대로 장면 재현
  1) 센터 로그인
  2) 긴급 공고 등록
  3) 강사 알림 수신
  4) 강사 수락
  5) 센터 매칭 완료 확인
  6) handoff note 표시
  7) GPS 체크인
  8) 센터 도착 알림
  9) 양측 완료 확인

각 단계에서 screenshot 저장:
test-results/demo-screenshots/
```

Playwright 공식 문서는 디바이스 에뮬레이션, geolocation, permissions, 브라우저 컨텍스트 사용을 모두 지원한다고 명시합니다. ([Playwright][3])

## 1분 영상의 가장 좋은 구성

당신 타겟에는 아래 구성이 가장 잘 먹힙니다.

### 0~5초

문제 제시
자막:
**“갑자기 강사 결근. 아직도 커뮤니티에 글 올리고 기다리시나요?”**

### 5~20초

센터가 긴급 공고 등록
자막:
**“긴급 공고 등록 10초”**

### 20~30초

강사에게 즉시 알림, 수락
자막:
**“가까운 강사에게 자동 디스패치”**

### 30~40초

인수인계 노트 표시
자막:
**“수업 내용과 회원 주의사항까지 전달”**

### 40~50초

GPS 체크인 + 도착 확인 + 완료 확인
자막:
**“노쇼 방지, 정산 분쟁 방지”**

### 50~60초

당신 얼굴 + CTA
자막:
**“실제로 쓸 의향 있으시면 20분만 인터뷰 부탁드립니다”**

이 구조는 업로드한 3개 Scene + 마무리 구성과 거의 동일하고, 센터장 관점 메시지에 맞춰져 있습니다.

## 절대 길게 하지 말아야 하는 이유

센터장 대상 콜드 아웃바운드 영상은 보통

* 기능 소개
* 개발 배경
* 비전 설명

이런 걸 넣는 순간 이탈합니다.

이 타겟이 원하는 건 딱 3가지입니다.

* **수업 펑크 막아주나**
* **노쇼 리스크 줄어드나**
* **커뮤니티보다 빠르나**

업로드한 문서의 타겟 관심사도 정확히 이 3축에 가깝습니다. 센터장은 “수업 펑크 방지, 노쇼 리스크 제거”, 강사는 “가까운 곳 빠른 매칭, 정산 투명성”에 반응하도록 정의돼 있습니다.

**“실제 앱을 이용한 1분 문제 해결형 데모 영상”**
